# Contributing

Small projects, small commits. If a change needs a paragraph of explanation it
usually belongs in two commits instead of one.

## Commit style

Short and imperative, with an optional scope:

```
fix(parser): stop at the first tab
docs: explain the layout
test: cover the empty directory case
```

The scope is the project or the part of it you touched. Keep the subject under
about seventy characters and put the reasoning in the body when it matters.
